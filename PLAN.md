# PLAN — Release Automation for TypeScript SDK

This document describes the plan to configure `semantic-release` to automate versioning, changelogs, and releases for the EasySQL TypeScript SDK.

## Proposed Changes

### 1. Release Configuration: `.releaserc.json`
Configure `semantic-release` using standard Node.js plugins:
- `@semantic-release/commit-analyzer`: Checks commit messages since the last release.
- `@semantic-release/release-notes-generator`: Creates Markdown release notes.
- `@semantic-release/changelog`: Updates the local [CHANGELOG.md](file:///home/joao/Workspace/clearsoft/easysql-sdk-ts/CHANGELOG.md).
- `@semantic-release/npm`: Bumps the version in [package.json](file:///home/joao/Workspace/clearsoft/easysql-sdk-ts/package.json) (and optionally publishes to npm registry if `NPM_TOKEN` is provided).
- `@semantic-release/git`: Commits the modified `package.json` and `CHANGELOG.md` files back to the repository.
- `@semantic-release/github`: Creates a GitHub release with the compiled release notes.

### 2. GitHub Actions Release Workflow: `.github/workflows/release.yml`
Create a new GitHub Action workflow that:
- Triggers on push to `main` or `master`.
- Installs Bun and runs quality checks (`make typecheck`, `make test`, `make build`).
- Runs `semantic-release` to release the package automatically.

### 3. Update Generation Workflow: `.github/workflows/generate-sdk.yml`
Update the PR title and commit-message generated by the auto-updater to match Conventional Commits (e.g., `feat(sdk): regenerate API types from OpenAPI spec`) so it triggers a release when merged.

## Verification

Run local dry-run to test config:
```bash
bun install
npx semantic-release --dry-run --no-ci
```
